开源理念

把"开源"落到可验证的细节上

公开源码只是起点。Keyper 关心的是：你能不能读得懂它做了什么、改得动它的设计、并且不必相信任何口头承诺。

本地优先

连接配置、应用设置与操作日志全部落在本机配置目录。运行期唯一的外部请求是更新检查，而且可以用 KEYPER_UPDATE_URL 指向内网镜像。

可审计的安全

沙箱、上下文隔离与 CSP 不是宣传语：脚本哈希由构建期脚本自动写入，npm run csp:check 能校验是否失配，策略本身可在源码里逐条对照。

引擎可插拔

引擎经注册表登记，配置、连接池、日志与搜索历史按引擎各自隔离。新增一种引擎是实现一个适配器并注册，不需要改动已有模块的代码路径。

透明的发布链路

推送与 PR 跑同一套门禁，标签触发打包，产物与 latest.yml、blockmap 一起公开；客户端做差分更新，只传输与本地版本不同的分块。

把贡献门槛做低

文案用语义 key，改译文不动调用点；漏译、占位符不一致、引用了不存在的 key，都会在 CI 里被 i18n:check 拦下，而不是等到运行时。

承认边界

没做代码签名、含凭据导出是明文、部分平台尚未产出安装包——这些写在文档里，而不是等用户踩到才发现。见下方「当前边界」。

双引擎

两套引擎，互不牵连

Redis 与 Memcached 作为彼此隔离的模块接入：连接池、IPC 通道、日志字段与搜索历史各走各的，一个模块异常不会影响另一个。连接列表带引擎角标，日志可按模块筛选。

  • 多 DB 切换 + 分页 SCAN + 模式匹配 + 前端二次筛选
  • 六种数据结构：string / hash / list / set / zset / stream，各自匹配对应的编辑语义
  • Pub/Sub 订阅：频道实底 chip、模式虚线 chip，可单个退订
  • 慢查询日志、键内存分析（按前缀聚合）、键空间通知位配置
  • 监控曲线：2 秒采样、保留 450 点，六个指标各一张折线图
  • SSH 隧道与多级跳板，生产实例也能安全直连
  • 内置 CLI：370 条命令补全、历史按连接持久化、结果直接回显
  • Stream 管理：消费组与 PEL、XACK / XCLAIM / XTRIM，低版本自动隐藏入口
  • Lua 运行器：全局脚本库、KEYS / ARGS、EVAL_RO 与 SCRIPT KILL
值类型与可写性
string 读写 hash 读写 list 读写 set 读写 zset 读写 stream 只读

stream 是追加写日志：改历史 entry 会破坏消费位点、删 entry 会造成消费缺口，因此只提供复制类操作。这是设计决定，不是没做完。

  • 全量键浏览走 lru_crawler metadump 遍历完整 LRU，修复仍处于 WARM 段的键重连后不显示
  • 旧服务端自动回退 stats cachedump，并如实标注「可能不完整」
  • 按全局「每页加载键数」分页，支持加载更多 / 加载全部，与 Redis 键区交互一致
  • 批量删除、TTL 修改、前缀重命名：逐键推进、可随时中止、目标已存在则跳过并标记失败
  • 统计与命中率、按 slab 分组、运行参数查看、flush_all
  • 监控页签与 Redis 共用同一套采样与绘图骨架，只把数据源换成 stats
与 Redis 的差异如何体现
  • 连接池 / 管理器 / IPC 通道各自独立
  • 日志模块字段可按引擎筛选
  • 键遍历方式LRU 遍历，非 SCAN
  • Ops/sec 换算相邻采样差值
能力清单

日常真的会用的那些事

下面每一项都对应已发布版本里的实际行为，可在源码与更新日志中逐条追溯。

大 key 分页加载

容器类型不再一次读全量：默认每页 500 条、上限 20000 条，「加载更多」按游标续取——hash / set 用 SCAN 游标，list / zset 用偏移量，stream 用上一页最后的 entry ID。刷新当前键按已加载数量重读，不会退回第一页。

虚拟滚动

五种表格类型与 string 逐行视图都只渲染视口内的行：可变行高实测缓存 + 前缀和二分查找 + 上下等高占位。万级元素的键也能流畅滚动，粘性表头、列宽拖拽与行内操作不受影响。

键列表原地增量刷新

刷新不清空列表、不闪骨架屏，按当前已加载数量重扫匹配模式；未变化的键复用原对象，列表行不重绘。选中键若不在新结果里，先单键查询核实，确认已被删除才清空值区。

值区多标签保活

切走的标签只隐藏、不卸载——筛选、排序、编辑草稿、列宽、滚动位置全部保留；切回已缓存的标签立即渲染并静默刷新。

全库搜索下沉主进程

SCAN 在主进程执行，边扫边推送进度、可随时中止；结果平铺虚拟滚动。键搜索历史按连接与库隔离，LRU 30 条并持久化。

批量操作面板

批量删除 / TTL / 前缀重命名走值区面板：清单可搜索排序，逐行显示当前值与目标值，执行时逐键推进并可随时中止，全部结束后只广播一次键列表刷新。

操作日志

只记录手动操作，按日期与连接筛选；表头吸顶、操作列固定右侧，横向滚动时列不漂移，五列支持升降序，文本按中文排序。

连接导入导出

导出为带格式头的 JSON，凭据默认剥离，勾选包含需二次确认；导入先出逐条预览（冲突 / 已连接 / 非法条目），默认新建 ID、可切换按 ID 覆盖。URI 批量导入支持注释、最多 200 行、逐行报错且只导入合法行。

应用内增量更新

在「检查更新」面板内直接下载并安装，走 blockmap 差分只传变化分块，显示百分比、已下载 / 总量与速度；面板可隐藏而下载继续，完成后可选「稍后」或「重启并安装」。

三语言界面

简体中文 / 繁體中文 / English，右上角即时切换并持久化，首次启动按操作系统语言自动选择；主进程文案（错误信息、日志）随设置同步切换。

九套皮肤

配色全部由 CSS 变量驱动，组件不感知主题——新增皮肤只需补一组变量。皮肤切换不重载窗口，首帧即生效，不会闪回默认主题。

错误落盘

渲染层与主进程异常写入 logs/errors-yyyymmdd.log，带堆栈与 5 秒去重，便于把一份日志直接贴进 Issue。

TTL 倒计时

键列表与值区每秒递减剩余时间；归零后向服务端复核一次——过期键从列表消失、值区清空，不会出现「倒计时已结束、界面还展示缓存」的错觉。

键收藏

树形与平铺视图共用一套收藏区，行内可单独移除；底部状态栏汇总收藏数与当前筛选命中，分组沿用全局键名分隔符。

值格式解码

自动识别 JSON / JWT / Base64 / PHP 序列化 / gzip / zlib / 图片 / Hex / MessagePack，检测结论写进状态栏，原文与解码视图一键切换，不猜二进制内容。

CLI 命令补全

内置 370 条命令目录：输入时展开补全面板，历史按连接持久化，结果可复制、可清屏；按连接分标签，会话互不串台。

Stream 管理

消费组与消费者明细、PEL 查看与 XACK / XCLAIM、单条 XDEL、XTRIM 裁剪；服务端版本不支持的能力直接隐藏入口，而不是点了才报错。

Lua 运行器

全局脚本库支持命名保存、单条与批量删除；KEYS / ARGS 传参，带 EVAL_RO 只读开关与 SCRIPT KILL。脚本原样交给服务端执行，权限等同于连接所用账号。

性能不是靠"感觉快"

安装包体积、构建产物体积、渲染耗时都被量化记录：Electron 运行时语言包从 50+ 种裁到界面真正使用的 3 种，渲染层依赖归入 devDependencies 使 asar 只含生产依赖，安装包从 84.0 MB 降到 75.4 MB（-10.3%），app.asar 从 18.9 MiB 降到 3.7 MiB。

安全

凭据只留在你这一侧

Keyper 没有账号体系、没有服务端，也没有把连接信息发往任何第三方的代码路径。下面是可以在源码里逐条核对的实现细节。

进程隔离

渲染进程开启 contextIsolation、关闭 nodeIntegration，并启用 sandbox: true：渲染层与 preload 都拿不到 require / process / module / Buffer，能力仅经 contextBridge 白名单暴露。

严格的 CSP

default-src 'none'，脚本走 sha256 哈希、样式不含 unsafe-inline。生产靠构建产物里的 <meta> 生效（file:// 下响应头无效），开发由主进程注入另一套带 HMR 放行的策略。首屏主题脚本的哈希由脚本在构建时自动写入，npm run csp:check 可校验是否失配。

凭据存储与传输

连接密码优先调用系统钥匙串（safeStorage）加密后落盘；仅在钥匙串不可用时降级为明文，并以 raw: 前缀显式标记。导出文件默认剥离凭据；显式勾选「包含凭据」后，Redis / SSH 密码、私钥与口令会以明文写入用户选择的文件并需二次确认——不做二次加密，需自行保管。

导航与外链

应用内导航、<webview> 挂载、Chromium 权限请求一律拒绝；外链交由系统浏览器打开，且只放行 https 与受信任域。

更新链路

自动更新从配置的 GitHub Releases（HTTPS）拉取，安装包与增量元数据必须同源发布；可用 KEYPER_UPDATE_URL 指向内网 / 镜像的 generic 更新源。未打包版本自动跳过自动更新，回退到版本页检查。

安装器环境检查

传统「检查 VC++ / .NET / Node.js」在这里是无效检查——运行时随包携带，主进程不调用任何外部程序。安装页实际检测会导致「装完打不开」的条件：Windows 内部版本 ≥ 17763、必须 x64（不通过硬性中止）、磁盘 ≥ 600 MB、安装目录实写探针文件。

当前边界

开源的价值在于把没做的事也写清楚。以下是已知边界，欢迎在 Issue 里讨论优先级。

  • 代码签名Windows 安装包目前未做代码签名，正式分发前应补齐，以避免 SmartScreen 告警。
  • 平台产物发布流水线当前产出 Windows NSIS 安装包；macOS / Linux 的打包配置就绪但尚未产出安装包。
  • 凭据导出勾选「包含凭据」的导出文件是明文，不做二次加密。
  • 钥匙串降级系统钥匙串不可用时凭据降级为明文存储，以 raw: 前缀标记。
  • JSON 美化只对 string 提供。容器类型本就是结构化展示，逐项缩进会让行高参差、信息密度下降——这是设计决定。
  • Lua 脚本运行器把脚本原样交给服务端执行，权限等同于当前连接所用账号；EVAL_RO 只是改用只读命令，不是沙箱。
安装与开发

三条路径，任选一条

下载安装包、从源码构建、或者只跑渲染层调界面——三者互不干扰。

Keyper-<最新版本>-win-x64.exeNSIS · x64

构建产物落在 release/<版本>/，同目录生成 latest.yml 与 *.blockmap（增量更新分块索引），安装目录内打包 app-update.yml（更新源配置）。安装包的 sha512 校验值以 Release 中的 latest.yml 为准。

  • Windows 10 1809（内部版本 17763）及以上，x64
  • 安装时把安装目录写入当前用户 PATH，卸载按分号边界逐段移除，重复安装不产生重复条目
  • 升级模式沿用原安装目录并保留 config/，用户数据不会被清掉
  • 安装向导为三段式（安装范围 / 安装目录 / 就绪确认），窗口运行时可放大，低分辨率屏幕也不挤

cd keyper
npm install

常见问题

可能会想先问的

数据会上传到任何地方吗？

不会。Keyper 没有账号体系也没有自己的服务端，连接配置、设置与操作日志都落在本机配置目录。运行期唯一的外部请求是自动更新检查，指向 GitHub Releases，并且可以用 KEYPER_UPDATE_URL 换成内网镜像。

为什么 stream 只能读不能改？

stream 是追加写的消息日志：改历史 entry 会破坏消费位点语义，删 entry 会造成消费缺口。所以值区只提供复制类操作，并明确标注只读——这是设计决定，不是没做完。

为什么 JSON 美化只对 string 提供？

只有整块文本才谈得上缩进重排。hash / list / set 本质已是结构化展示，逐项缩进会让行高参差、一屏内信息密度下降；zset 的 member/score 与 stream 的固定结构更没有美化空间。

支持哪些服务端版本？

Redis 7.x 及以上（字段级 TTL 等能力按版本探测，低版本会隐藏对应入口并在状态栏说明原因）；Memcached 优先使用 lru_crawler metadump，旧服务端自动回退 stats cachedump 并标注结果可能不完整。

有 macOS / Linux 安装包吗？

electron-builder 的 DMG / AppImage + deb 配置已就绪，但发布流水线目前只产出 Windows NSIS 安装包。可以在源码里用 npm run dist 为当前平台打包。

许可证是什么？

仓库的 LICENSE 文件是 Apache License 2.0。注意 package.json 的 license 字段目前写的是 MIT，两者不一致——以 LICENSE 文件为准，这个字段应当被修正。

代码是唯一不会过期的文档。从 electron/services/engines/registry.ts 开始，二十分钟能看懂引擎是怎么插进去的。
