连接列表项 · 阴影 10 套方案

对象是左侧连接栏里的单个连接磁贴（236px 宽、10px 圆角、56px 最小高）。 现状完全无阴影，只靠一层"比面板略亮"的底色和 1px 边框区分。 每套方案都并排给出暗色 / 亮色两版，并含 选中态（红色描边环）、已连接（绿点）、连接失败（红点）三种状态下的真实观感。 所有方案都刻意避开用 box-shadow 表达选中态——真实代码里选中态的描边环已改为 ::after 伪元素，阴影层可以独占。

页面主题切换只影响外层画布；每套方案内部已固定并排双主题，便于直接对比。
01

现状（对照）：无阴影，只靠底色 + 1px 边框

条形磁贴完全贴在面板上，层级靠"比面板亮一档"的填充色

现状
  • 识别边框 + 淡底，没有任何投影。
  • 问题 1列表一长就是一摞"色块"，磁贴与面板之间没有空间关系，看起来像表格行而不是可点的卡片。
  • 问题 2状态点（顶部 16×2px 短线）与卡片同层，已连接的绿线常被误认为边框高光而不是状态。
  • 问题 3鼠标悬停只换底色，没有任何"浮起"反馈，点击前的确认感弱。
02

柔和单层投影：0 1px 2px + 0 2px 6px

双层同向投影，近处紧、远处散，是"卡片浮在面板上"最通用的写法

最稳妥
  • 优点不改变尺寸与布局，只加一层 box-shadow，落地成本最低。
  • 优点暗色下几乎"看不见阴影"却看得出层次；亮色下明显浮起，两套主题都不会翻车。
  • 代价列表密集时（gap 仅 4~6px）上下两张卡的投影会叠在缝里，形成一条略脏的暗带。
03

贴地细影：0 1px 1px，只留 1px 视觉缝隙

极小偏移、极小模糊，模拟"卡片与面板之间只有一张纸的厚度"

最克制
  • 优点密度友好：即便 4px 间距也不会糊成一片，长列表里最耐看。
  • 优点暗色下提供了一条极细的"下沿加深"，卡片边界比纯边框清楚，但不会像投影。
  • 代价存在感很弱——如果目标是"让用户看出这是可点的卡"，它几乎不解决问题。
04

硬边落地影：0 2px 0 实心推移

不做模糊，直接把卡片"抬"起 2px 并投出一条硬边，按下时收回

最有手感
  • 优点硬边影给出明确的"厚度"，hover 时把偏移收到 1px 有一点点按压感，交互反馈最强。
  • 风险风格明显偏"实体按钮"，与项目整体的扁平、克制气质有偏差；多套皮肤下容易显得玩具化。
  • 代价投影硬边会在 4px 间隙里形成明显横线，密集列表观感偏吵。
05

内阴影浮雕：上缘高光 + 下缘暗边

不用外投影，改用 inset 在卡内造一条顶部亮线、底部暗线

不占外部空间
  • 优点完全不向外扩散，密集列表里零干扰——这是它相对 02 的最大优势。
  • 优点暗色下"顶部一道亮边"非常像实体按键的边缘受光，质感高级且不抢内容。
  • 代价本质是"卡片凹陷"而非"浮起"，语义与"可点击卡片"略有出入；亮色下效果偏弱。
06

描边 + 投影：1px 深描边打底，再接一层柔影

先用 0 0 0 1px 做一圈比边框更深的轮廓，再加 0 2px 5px

轮廓最清楚
  • 优点在 9 套皮肤下最稳：轮廓靠"深一圈的描边"保证，不依赖投影对比度，换肤不会失效。
  • 优点可以顺手把现有 border 去掉，改由阴影描边承担——少一条 1px 边框的"硬线"。
  • 代价描边 + 边框同时存在时会形成 2px 视觉厚度，必须先去掉 border 再上这套，否则显笨重。
07

仅 hover 浮起：常态无影，悬停才投 0 2px 8px

阴影作为"指针在哪儿"的反馈，而不是常驻装饰

最省视觉预算
  • 优点常态列表保持绝对干净，只有被指到的那一张浮起——注意力分配最符合"用户在找某一条"的场景。
  • 优点不会出现 02 的叠影问题；密集列表也不脏。
  • 风险用户要求的是"增加阴影效果"，只在 hover 出现可能不满足预期；且触屏/键盘操作时看不到这层反馈。
08

引擎色光晕：暗色下投出一圈同色柔光

阴影色不用黑，而用 --eng（Redis 红 / Memcached 紫），中性色打底 + 彩色外扩

最好看
  • 优点暗色下彩色光晕比黑投影更"活"，一眼能看出这组连接属于哪个引擎，和左侧栏的引擎色语言一致。
  • 优点color-mix 直接由 --eng 推导，9 套皮肤自动跟随，不用逐皮肤写死颜色。
  • 风险彩色光晕最容易"过火"：一旦透明度调高就像霓虹灯；亮色主题下几乎失效（白底吃不出彩色阴影）。
09

分层双影：近影锐 + 远影散，模拟景深

0 1px 1px 定轮廓、0 6px 14px -4px 造景深，负扩展避免外扩过大

质感最好
  • 优点用负 spread 把大模糊收在卡片正下方，既有景深又不像 02 那样在缝隙里外溢。
  • 优点近影提供"锐利边缘"，远影提供"体积感"，是专业设计系统里最常见的双层配方。
  • 代价参数需要按深浅两套主题分别调，直接复用同一组数值时亮色会偏灰、暗色会偏淡。
10

选中态加重：常态轻影，选中与连接的卡加深 + 彩色投影

阴影随状态分级：常态 2px、hover 5px、选中/已连接 10px 并带引擎色

状态最清楚
  • 优点把阴影变成状态语言：一眼看得出哪条正连着、哪条被选中，补上了现状"绿线太弱"的问题。
  • 优点可以替代现在的 inset 0 0 0 1px 选中描边，选中态不再需要额外边框。
  • 风险状态一多，阴影规则也变多（常态/hover/选中/连接/错误 × 暗亮两主题），是十套里维护成本最高的一套。

我的推荐顺序

  • 首选 09（分层双影）：近影定轮廓、远影造景深，密集列表下不糊，是质感与可维护性平衡最好的一套。
  • 次选 02（柔和单层）：一行 box-shadow 搞定，任何时候都能退回，适合先上线再迭代。
  • 若重点是"看得出哪条正在连"：选 10，把阴影和状态绑定，顺带替掉现有的选中描边。
  • 不建议 04 / 08：04 的硬边影与项目扁平气质冲突；08 在亮色主题下基本失效，双主题一致的成本最高。
