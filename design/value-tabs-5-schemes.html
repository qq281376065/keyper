值区底部 多键标签栏 · 5 套方案

现状：值区底部是一条统计状态栏（.viewer-foot），显示当前键的类型、字段数、大小、最长字段等。 目标：在这条底栏位置支持同时打开多个键、快速切换查看，同时不丢掉原有的统计信息。 因为标签在底部，方案的核心差异在于三件事：选中态如何与上方内容建立联系、 统计信息放在哪里、标签多了以后如何折叠。下面 5 套方案共用同一份值区模拟，可直接点击标签、关闭标签、从左侧开新标签。

01

票根标签 Ticket Tabs

把值区头上的票根语言延伸到页脚：标签像一排撕下的票根，选中项升高 5px、顶部用类型色封口，并在左右各咬出一个半圆撕口；统计信息常驻右端。

备选 · 信息最全
设计意图底部标签最怕“和内容没关系”。上浮 + 类型色封口 + 撕口，让选中项像从上方内容里垂下来的票根，归属感最强。
优点与现有票根头部是同一套视觉；右端保留紧凑统计，原状态栏信息不丢；38px 只比现状多几像素。
代价长键名需要截断；右端统计在窄窗口下会被压缩，建议窄窗时自动隐藏次要项。
02

胶囊条 Pill Strip

底栏变成一条胶囊工具条：每个键是一枚带类型色圆点的胶囊，选中项使用类型色浅底；最左侧显示已打开数量，最右侧固定统计信息。

改动最小
设计意图复用工具栏里已有的胶囊 / 分段控件语言，不引入新的形状；底部只做“切换器”，不做“页签”。
优点落地成本最低，DOM 和样式都简单；胶囊比页签窄，同样宽度能放更多键；视觉与现有按钮体系最一致。
代价没有页签的“纸张”结构，更像筛选 chip；需要靠计数徽标和选中底色强调“这些是已打开的键”。
03

双层底栏 Tabs + Status

上排是页签，下排原样保留现有状态栏。选中页签顶部用品牌红压线，与上方内容区相连；底部 24px 统计行一字不改地迁移过来。

信息零损失
设计意图不赌“统计信息可以收起来”。页签负责切换，状态栏继续负责读数，两块职责彻底分开。
优点迁移成本最低，统计代码几乎原样保留；用户不需要重新学习信息位置；页签可以做得更薄。
代价整条底栏 56px，比现状多占约 24px 垂直空间；键多时上下两排都显拥挤。
04

折叠脊标 Spine Tabs

未选中的标签折叠成 58px 的“书脊”，只留类型字母和 3~4 个字符；选中项展开为 246px，键名下方直接内嵌「字段 / 大小 / TTL」。左端是数量徽标，右端是「更多」菜单。

多键优先
设计意图把状态栏“折叠进选中的标签里”。视野内所有标签都可见，选中的那个自然成为当前键的信息卡。
优点10 个以上键也不挤；可完全移除独立状态栏；溢出有「更多」菜单兜底，适合键间反复比对。
代价未选中标签只能看到类型和几个字符，需靠 tooltip / hover 展开补偿；hover 展开会推挤相邻标签，动效要克制。
05

悬停书签 Hover Bookmarks

30px 极简书签条：最左是固定的 「详情」（房子图标 + 当前连接概览，永远第一位、不可关闭），其后是 ‹ › 方向滑动与无缝书签（类型色点 + 键名，长键名保留头尾、中间省略），右端只留 ⋯ 更多操作。键数量与统计信息都不再常驻，把横向宽度全部让给标签；更多菜单里可搜索已打开的键、批量关闭，统计由独立的悬停统计卡按需给出（见 06）。

拟选定
设计意图「详情」常驻第一位，作为这只连接的“主页”；键标签只回答打开了哪些键，箭头解决装不下，更多菜单解决找不到 / 批量关。常驻统计全部撤掉，宽度优先给标签。键名超长时保留头尾，因为 Redis 键的区分度常在尾部。
优点30px 与现状几乎一致，且没有统计区争抢宽度；12 个键靠箭头 + 滚轮逐一可达，更多菜单内置搜索，标签再多也能一键定位；关闭全部键后自动回到详情，不出现空占位；长键名不会撑爆标签，title 与悬停卡可看全名。
代价键总数只能打开菜单看；详情标签固定占约 60px；悬停浮层会遮住内容底部；更多菜单多一次点击，极端长键仍需悬停看全名。
06

悬停统计卡 Key Stats Popover

从 05 中拆出的独立组件：卡片只负责“解释这个键”，触发面可以有很多——底部书签、左侧键列表、搜索结果、命令面板。05 的底栏因此可以维持 30px 只做切换，卡片单独迭代。

独立组件
Card · 常规键
固定顺序：TTL / 统计 / 编码；键名最多两行完整显示。
Card · 临近过期
TTL ≤ 5 分钟时数值转为强调色并附加标记。
Triggers · 两处入口，同一张卡
底部书签
左侧键列表
悬停任意一处，卡片出现在触发元素上方，并带一个指向它的箭头。
定位默认在触发元素上方 8px；上方空间不足时翻到下方；左右钳制在视口内 8px。
时机悬停 90ms 后出现；移出即消失；滚动、Esc、切换标签立即隐藏。
键盘聚焦标签或列表行同样显示；卡片 pointer-events: none，不抢焦点。
解耦入参只有键对象；颜色取类型令牌，不改底栏也能单独上线。
设计意图“切换”和“解释”分开：标签条回答打开了哪些键，卡片回答这个键有多大、多久过期、什么编码。
优点一处实现、多处复用；信息可以比状态栏更完整，却没有常驻成本；05 的底栏因此能保持 30px。
代价触屏无悬停，需保留点击入口；浮层遮挡内容底部约 80px，所以必须轻、必须及时消失。

落地要点（五套共用）

  1. 状态模型：新增 openKeys: string[] 与 activeKey: string | null，并允许特殊值 'detail' 表示连接详情页。不要复用单个 selectedKey，否则无法表达“打开了但未激活”。
  2. 视图状态隔离：每个键的搜索词、排序、滚动位置、行内编辑草稿按 key 存一份 Map；切回标签时原样恢复，这是多键查看的核心体验。
  3. 键生命周期：重命名同步标签文字；删除键后关闭对应标签并自动激活右邻；TTL 变化只更新当前激活键的统计。
  4. 交互补齐：滚轮 / 方向键横向滚动、激活标签自动滚入视野、中键 / Ctrl+W 关闭、Ctrl+Tab 切换、右键「关闭其他 / 关闭右侧」。固定「详情」标签不参与滚动、批量关闭，也不显示关闭按钮；更多菜单内置搜索（回车切换首项、上下键浏览）。
  5. 长键名：书签按「头 12 + … + 尾 8」截断（尾部通常才是区分位），title 提供全名，悬停卡最多两行完整显示；不要依赖末尾省略。
  6. 零标签：所有键标签关闭后自动回到固定的「详情」标签，不再显示“未选择键”的占位文案。

建议

  • 先落地 05：30px≈现状高度；两端箭头 + 滚轮 + ⋯ 更多菜单把“很多键”这条短板补齐。
  • 06 并行独立开发：卡片不依赖标签栏，先挂键列表也能用，之后直接复用到书签。
  • 若后续反馈“信息找不到”，再升级到 01 票根标签（统计常驻），两者共用同一份状态模型。
  • 五套共用同一份 DOM 契约（open 列表 + active id），样式层切换即可，不必重写逻辑。
